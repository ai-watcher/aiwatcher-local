# Optimize review contract

Optimize surfaces possible organization work, not proven safe cleanup. The copied prompt starts with a read-only review and requires explicit approval of the final action summary before a separate owning-tool action. AIWatcher itself never executes cleanup.

## What the reviewer receives

Optimize is disk-first for AI workspaces and recovery-first for unlanded work. Historical session volume is not a disk-cleanup signal and does not rank candidates. Session metadata is used only to protect a checkout with recent exact-path activity or to explain linked work.

Local inspection reads only the first metadata record (at most 64 KiB) and last 64 KiB of an exact observed Codex JSONL file. Results are cached by path, ID, file size and modification time. Only identity and lifecycle metadata leave this reader. Prompt text, final response text, command arguments and source are not included in the packet. A missing event or unreadable/mismatched log remains unknown. Other tools without this Codex metadata stay unknown rather than inheriting a guessed role.

Fresh Start groups preserve exact receipt and source-session IDs. Runtime packets carry bounded PID/parent/tool/working-directory/session/stale-signal observations; the review command must be rerun for current ownership. Workspaces require the reviewer to check current Git state, unpushed work and dependencies. No background network PR lookup is performed by Optimize.

Workspace discovery covers registered worktrees of known projects, system temp roots, Codex's worktrees root, and each project's `.worktrees` and `.claude/worktrees`. The filesystem walk is bounded to depth three and 1,200 directories per root. Nested Codex containers such as `~/.codex/worktrees/<id>/<repository>` are traversed until the exact Git root is found; the opaque `<id>` container is not reported as a checkout. Temporary Git checkouts on `codex/`, `claude/`, or `agent/` branches can be discovered regardless of directory name. Tool-named non-Git folders remain inferred candidates; symlinked directories are skipped. Arbitrary locations, detached unnamed clones and unrecorded command working directories can be missed. The first eight candidates are returned with total and omitted counts; this is not an exhaustive machine scan.

Workspace packets carry bounded allocated local bytes, branch, upstream, dirty/untracked counts, observed HEAD/common Git directory, local-main patch equivalence, directory timestamp, matching process CWDs and linked session IDs. Hard-linked allocation is excluded from reclaim totals because another link—even in another worktree—can keep those blocks alive. Platforms without allocated-block metadata fall back to a clearly non-notifying logical estimate. A bounded size is labelled as a lower bound. The walk is cached for five minutes and capped at 50,000 entries or 0.5 seconds per workspace. Discovery, disk, and Git evidence share a two-second global audit budget; candidates reached after that budget remain **Needs evidence** rather than delaying the dashboard or being guessed safe.

Workspaces are grouped as **Ready to review**, **Needs preservation**, **Needs evidence**, or **Active · keep**. Ready requires a registered worktree that is clean, inactive, has no patch-unique commits beyond a local main reference, and has complete runtime-to-working-directory coverage. AIWatcher reads actual process CWDs on Linux and macOS when command flags omit them. Windows, process-inventory failure, and any inaccessible process CWD fail closed to **Needs evidence**. Dirty, untracked, unlanded, active, standalone, or uncertain work is never classified ready. Git checks use local refs without fetching, so the final reviewer must still verify current remote main before any separately confirmed removal.

Disk candidates rank by safety state and measured bytes, not tokens or session count. The Companion interrupts for disk cleanup only when ready worktrees total at least 500 MB of allocated-byte evidence; smaller, logical-only, or protected findings remain visible in Control without an interruption. Unlanded-work recovery can still interrupt independently because its value is preservation rather than disk relief. If recovery and disk findings coexist, the Companion leads with **Protect work** and leaves the space review in Control.

## Review and confirmation

The independent reviewer must match exact owning-app identities, inspect the latest ask and final response, check unresolved work, current parent/project activity, actual checkout and runtime. The reviewer returns a decision table and a confirmation question naming only verified items. If evidence is missing, the next request is verification rather than cleanup approval.

Both basic and AI-assisted prompts require a fresh final action summary immediately before any separately authorized owning-tool action. It names exact targets and actions, verified reasons, outstanding risks, preserved work, recovery or irreversibility, and measured relief (or unknown). Explicit user confirmation applies only to that summary; changed evidence or targets require another confirmation. A general cleanup request or Reviewed receipt is not approval. Reversible archiving is distinguished from permanent deletion. After exact approval the reviewer may execute the supported owning-tool action and verify the result. Registered worktrees use Git removal without force; shared repository and branches are preserved. A refusal must be reported rather than bypassed.

Basic Copy cleanup prompt fetches the current canonical packet through the same refresh endpoint used by review and AI composition; it never copies a prompt string embedded in the page. Copy all also fetches the current queue. During initial loading, cache migration, background refresh or an evidence error, the page shows a visible status instead of copy/review controls. The server rejects those actions until current evidence is ready. Legacy disk snapshots are invalidated and legacy memory candidates trigger a refresh.

The dashboard's Review decision dialog confirms a local review receipt only, never an archive/completion action. It refreshes available local log/runtime metadata before opening and before saving. An evidence mismatch returns HTTP 409 and requires reopening the summary. Receipt suppression is scoped to candidate ID plus stable evidence hash for 24 hours; changing relative display labels such as “5h ago” does not resurrect a card, while changed underlying activity does. Legacy project-scoped receipts remain readable and expire after 24 hours. Protected and active groups offer evidence review and **Keep protected**, not cleanup prompts.

AI composition cannot preclassify an item as safe. It preserves the complete local packet, adds optional verification questions, rejects non-array/non-string JSON values and refuses oversized inputs rather than truncating identities or guardrails. Contract versioning invalidates old cached prompts. Historical tokens represent past recorded activity; RAM/disk/context/cost savings are unknown unless separately measured.

AI Assist cache storage preserves up to 32,000 characters intact rather than clipping at 12,000. Optimize cache reads require a content integrity hash; legacy/unverified entries are regenerated and oversized outputs are rejected without partial storage. Confirmation and guardrails must survive both immediate composition and cache replay.

Companion copy leads with measured, actionable value in a short native-overlay line, for example “2.5 GB · 4 clean AI worktrees ready.” Protected or active bytes are never presented as reclaimable. Fresh Start and runtime evidence remain separate workflow groups and do not inflate the disk claim.

For macOS bundled desktop apps and helpers, PPID=1 alone is not treated as an orphan signal: launchd ownership does not establish abandonment. Independent signals such as a suspended state or missing working directory can still surface review candidates. RSS is a changing observation, not guaranteed reclaimed RAM. Organization-only chat groups must not be presented as resource savings.

## Validation

Python tests cover nested Codex roots, bounded and globally budgeted size measurement, clean/landed classification, dirty and unlanded preservation, recent-file and incomplete-runtime protection, the 500 MB notification threshold, stable receipt suppression, role/parent identity, privacy, receipt expiration and snapshot confirmation. Node tests cover safety-group rendering, protected-card actions, stale dialog responses, cancellation and the exact confirmed receipt payload.
